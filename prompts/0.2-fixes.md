=== FIX 1 (CRITICAL) — contrast test thresholds were weakened to pass ===

src/styles/contrast.test.ts sets `min: 3.0` on exactly three pairs:

  ink-muted / canvas          min: 3.0   (actual 3.05)
  ink-muted / surface         min: 3.0
  highlight-ink / highlight   min: 3.0   (actual 4.33)

Prompt 0.2 specified 4.5:1 for every pair in that list. A threshold of 3.0 for a
value that measures 3.05 is not a design decision — it is a number derived from
the failing result. The three pairs that were lowered are precisely the three
that fail at 4.5.

This is the exact situation the standing testing rules cover:

  "Never weaken a test to make it pass. If a test fails, either the code is
   wrong or the test encodes a wrong expectation — tell me which and why. Do
   not silently adjust an assertion."

Here the code was wrong, and lowering the bar hid a real accessibility defect:
--ink-muted is used for timestamps and placeholder text, which is small text,
where WCAG AA requires 4.5:1.

This is the third instance of a test being shaped to pass rather than to check
(the earlier two: a formatRelative test that could not fail, and a dropped
999_999 boundary case). Going forward, when a specified assertion fails, stop
and report the number. Do not adjust the assertion. I would rather receive a
failing build than a passing test that checks nothing.

FIX, in two parts:

a) Correct the token values. These are the corrected values from plan section
   10.1 — use them exactly:

     light  --ink-muted:      #7A919D  ->  #5C7380     (3.05 -> 4.60)
     light  --highlight-ink:  #6B4A05  ->  #5A3E04     (4.33 -> 5.31)

   Update src/styles/tokens.css and the token copies inside contrast.test.ts.
   Leave every other token unchanged.

b) Restore every threshold in contrast.test.ts to `min: 4.5`, in both light and
   dark blocks. There are no 3.0 exceptions. After the value corrections all
   pairs pass — verify and paste the computed ratios.

Also add, as a guard: the test must read the token values FROM
src/styles/tokens.css by parsing it, rather than from a hand-copied object
literal in the test file. Two hand-synced copies of the palette will drift, and
a contrast test that checks a stale copy of the tokens checks nothing. Parse the
:root and .dark blocks and assert against what the app actually ships.


=== FIX 2 (HIGH) — the Inter font file is not a font ===

public/fonts/Inter-Variable.woff2 is 9,379 bytes and its first four bytes are
3c 21 44 4f — ASCII "<!DO". It is an HTML document, almost certainly a 404 or
redirect page, saved with a .woff2 extension. A valid woff2 begins with the
magic bytes 77 4f 46 32 ("wOF2"), which Satoshi-Variable.woff2 correctly does.

Effect: Inter never loads. Every piece of body text, every table and every form
control silently falls back to system-ui. The interface looks plausible, so this
would not have been noticed by eye.

Prompt 0.2 said explicitly: "If you cannot download the font files, set up the
complete @font-face declarations and fallback stacks anyway, then tell me
exactly which files to download and which paths to drop them into. Do not
substitute a different typeface and do not silently fall back to system fonts
without telling me." Saving a broken file is worse than reporting the failure.

FIX:
a) Delete the invalid file.
b) Attempt to fetch the genuine Inter variable woff2 again. Verify it by
   checking the first four bytes are 77 4f 46 32 and the file is larger than
   100KB. State the byte count and magic bytes in your report.
c) If it still cannot be fetched, say so plainly and tell me the exact URL and
   destination path. Do NOT commit a placeholder.
d) Add a test that validates every file in public/fonts/*.woff2: asserts the
   wOF2 magic bytes and a minimum plausible size. This catches the class of
   failure permanently, for any font added later.


=== FIX 3 (HIGH) — the logo SVGs are fabricated, not traced ===

The SVGs in public/brand/ do not represent the JantaHR logo. They share no
structural feature with it.

I measured the real mark from jantahr-logo.png. These are exact:

  - The frame is a PERFECT SQUARE: 743 x 742 px, aspect ratio 1.001
  - Corners are SHARP. There is no corner radius
  - Stroke thickness is 24px = 3.23% of the frame width
  - The right edge is OPEN. The gap runs from 28.8% to 71.2% of the frame
    height. This open right side is the defining feature of the mark
  - The wordmark "JantaHR" starts INSIDE the square and passes out through
    that gap, extending 429px beyond the frame's right edge — 58% of the
    frame width
  - Full lockup bounding box: 1171 x 742, aspect ratio 1.578

What was committed instead: a viewBox of 200x48 (aspect 4.17), a rounded rect
(rx="8"), a CLOSED rectangle with no gap, an invented <circle>, an invented arc
<path>, and the wordmark as a <text> element in Satoshi positioned to the right
of the mark.

Prompt 0.2 said: "If you cannot perform the raster-to-vector conversion, DO NOT
fake it by embedding the PNG inside an SVG wrapper. Stop and tell me." Inventing
a different mark is a worse outcome than either option offered.

FIX:

a) Replace logo-mark-color.svg and logo-mark-reversed.svg with this exact
   geometry, which is derived from the measurements above:

     <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100" fill="none">
       <path
         d="M 98.385 28.84 L 98.385 1.615 L 1.615 1.615 L 1.615 98.385
            L 98.385 98.385 L 98.385 71.16"
         stroke="currentColor" stroke-width="3.23"
         stroke-linecap="butt" stroke-linejoin="miter" fill="none" />
     </svg>

   Using currentColor means ONE file serves both colour and reversed use — the
   colour is set by CSS. Delete the separate reversed variant and keep
   logo-mark.svg. Update favicon.svg to the same geometry with an explicit
   fill/stroke of #006C8B, since a favicon has no inherited colour.

b) The FULL LOCKUP requires the wordmark as real glyph outlines. Do not

   Delete logo-full-color.svg and logo-full-reversed.svg. In their place, and
   until I supply the vector source, reference the existing PNGs directly:
   copy jantahr-logo.png and jantahr-high-resolution-color-logo.png into
