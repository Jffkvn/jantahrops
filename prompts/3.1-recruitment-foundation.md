=== 1. SCHEMA ===

  create type public.vacancy_status    as enum ('draft','open','paused','closed');
  create type public.employment_type   as enum ('full_time','part_time','contract','temporary','internship');
  create type public.application_stage  as enum
    ('new','screened','shortlisted','interview_scheduled','interviewed',
     'rejected','offered','hired','talent_pool');
  create type public.availability_status as enum ('immediate','one_month','three_months','not_looking');

  create table public.vacancies (
    id              uuid primary key default gen_random_uuid(),
    organisation_id uuid references public.organisations(id) on delete set null, -- the client hiring
    title           text not null,
    slug            text not null unique,
    summary         text,
    description     text,
    requirements    text,
    location        text,
    employment_type public.employment_type,
    salary_min_ugx  bigint,
    salary_max_ugx  bigint,
    status          public.vacancy_status not null default 'draft',
    is_public       boolean not null default false,   -- shows on the website job board
    published_at    timestamptz,
    closes_at       date,
    owner_id        uuid references public.profiles(id) on delete set null,
    created_by      uuid references public.profiles(id) on delete set null,
    created_at      timestamptz not null default now(),
    updated_at      timestamptz not null default now()
  );
  -- indexes: status, is_public, organisation_id, owner_id, slug, created_at desc
  -- check (salary_min_ugx is null or salary_max_ugx is null or salary_max_ugx >= salary_min_ugx)

  create table public.candidates (
    id                    uuid primary key default gen_random_uuid(),
    contact_id            uuid not null references public.contacts(id) on delete cascade,
    headline              text,
    years_experience      integer,
    skills                text[] not null default '{}',
    education             jsonb not null default '[]',
    work_history          jsonb not null default '[]',
    salary_expectation_ugx bigint,
    availability          public.availability_status,
    cv_file_id            uuid,                         -- → candidate_files
    cv_parsed             jsonb,                        -- AI-populated later (§7)
    cv_parsed_at          timestamptz,
    -- embedding vector(1536) — added in §7 only if pgvector is available; do NOT
    -- add it in this task unless the extension enables cleanly. Search here is
    -- full-text (below), not semantic.
    rating                integer,                       -- 1..5, internal
    is_available          boolean not null default true,
    source                text,
    notes                 text,
    owner_id              uuid references public.profiles(id) on delete set null,
    created_at            timestamptz not null default now(),
    updated_at            timestamptz not null default now(),
    unique (contact_id)                                  -- one candidate profile per person
  );
  -- indexes: is_available, owner_id, skills (GIN), created_at desc
  -- Full-text search: a generated tsvector over the contact's name + headline +
  -- skills + notes, GIN-indexed. Because name lives on contacts, build the tsv
  -- from candidates' own columns (headline, array_to_string(skills,' '), notes)
  -- and search names via a join to contacts (the search API resolves both).

  create table public.applications (
    id           uuid primary key default gen_random_uuid(),
    vacancy_id   uuid not null references public.vacancies(id) on delete cascade,
    candidate_id uuid not null references public.candidates(id) on delete cascade,
    source       text,
    stage        public.application_stage not null default 'new',
    applied_at   timestamptz not null default now(),
    owner_id     uuid references public.profiles(id) on delete set null,
    notes        text,
    rejected_reason text,
    created_at   timestamptz not null default now(),
    updated_at   timestamptz not null default now(),
    unique (vacancy_id, candidate_id)                    -- one application per person per vacancy
  );
  -- indexes: vacancy_id, candidate_id, stage, owner_id

  create table public.interviews (
    id             uuid primary key default gen_random_uuid(),
    application_id uuid not null references public.applications(id) on delete cascade,
    scheduled_at   timestamptz,
    mode           text,                                 -- 'in_person'|'video'|'phone'
    panel          text[] not null default '{}',
    feedback       text,
    rating         integer,                              -- 1..5
    outcome        text,                                 -- 'pass'|'fail'|'hold'
    created_at     timestamptz not null default now()
  );
  -- index on application_id

updated_at triggers on vacancies, candidates, applications.

Stage-change logging: a trigger on applications that writes an activity

=== 4. PUBLIC JOB-BOARD ENDPOINT (Edge Function) ===

The JantaHR website has a job board that reads from a configurable endpoint
(env VITE_JOBS_ENDPOINT) and falls back to a static /data/jobs.json. The
website normalises a payload of either `[...]` or `{ "jobs": [...] }`. Ops
becomes that endpoint.

Function `public-jobs` (GET, --no-verify-jwt, CORS, edge-cached 60s):
- Returns { "jobs": [ ... ] } for vacancies where is_public = true AND status =
  'open', ordered by published_at desc.
- Each job object — match the website's Job shape as closely as possible.
  Provide these fields (the website cutover doc, §8, notes that field NAMES must
  be verified against the website's src/data/jobs.ts Job type and mapped if
  they differ):
    { id, slug, title, location, employmentType, summary, description,
      requirements, salaryMin, salaryMax, postedAt, closesAt }
  Never expose the client organisation, owner, internal notes, or any
  non-public vacancy. Salary fields are included only if the vacancy has them.
- Deploy: supabase functions deploy public-jobs --no-verify-jwt.

Write docs/JOBS_CUTOVER.md: set the website's VITE_JOBS_ENDPOINT to
`https://qjsgqskigjqrzjftunhg.supabase.co/functions/v1/public-jobs`, verify the
board renders, and confirm the Job field names match (map in the endpoint if
not). Note the static jobs.json stays as the fallback until Ops is trusted.


=== 5. PUBLIC CANDIDATE-REGISTRATION ENDPOINT (Edge Function) ===

Function `public-candidates` (POST, --no-verify-jwt, CORS). Talent-pool
self-registration, optionally tied to a vacancy slug. Mirror public-leads'
protections exactly.

Two-step upload (a CV is a file, so the browser needs a place to put it):
- The endpoint issues a short-lived SIGNED UPLOAD URL for the CV into the
  private `candidates` bucket when asked (action:'get_upload_url', with a
  filename + declared mime in the allowlist), returning { path, token } or a
  signed URL the browser PUTs to. Then the registration POST references that
  path. (If simpler in your stack: accept the file via multipart and upload
  server-side — either way the file lands in the private bucket, never public.)

Registration payload (write-only, returns {"ok":true}/{"ok":false,error}):
  { fullName, email, phone, headline, skills (comma string or array),
    yearsExperience, salaryExpectation, availability, cvPath (from the signed
    upload), vacancySlug (optional), honeypot, submittedAt }

Behaviour (in one logical flow, service-role client):
- honeypot filled → {"ok":true}, create nothing.
- validate: fullName required; email OR phone required. Normalise phone to
  E.164. MIME/size already enforced at upload.
- idempotency + rate limit: reuse the web_submissions table (lead_type
  'candidate') keyed on (email/phone, submittedAt); per-IP rate limit; 10KB
  body cap (the CV is uploaded separately, so the JSON stays small).
- find-or-create contact (email then phone); add the 'candidate' role;
  find-or-create the candidate profile (unique on contact_id) — on an existing
  candidate, UPDATE the profile fields and replace cv_file_id, do not duplicate.
- record the CV in candidate_files, set candidates.cv_file_id.
- if vacancySlug matches an open public vacancy → create an application
  (stage 'new', source 'website'); else the candidate simply enters the talent
  pool.
- write an activity on the candidate. Notify staff (reuse whatever public-leads
  does; if that's just a row, fine — email is the reminders slice).
- The bucket is PRIVATE. The endpoint NEVER returns the CV or any stored data.

CV PARSING IS NOT IN THIS TASK. Store the file and leave cv_parsed null. §7.


=== 6. SIGNAL: candidate_waiting ===

Add a rule to generate_signals(): an application sitting in a non-terminal stage
('new','screened','shortlisted','interview_scheduled') with no activity for
> 5 days generates a 'candidate_waiting' signal (severity 'warn') on
subject_type='application', title like "<name> is waiting on you for <vacancy>",
suggested_action 'Move stage or send an update'. Idempotent + 3-day dismissal
cooldown, exactly like lead_going_cold. Expires when the application moves or
gets activity.
