=== 9. FOUNDATION UTILITIES ===

These four files lock down decisions that would otherwise get re-invented
inconsistently across ten later features. Write them now, with tests.

src/lib/cn.ts
  Standard clsx + tailwind-merge helper: `export function cn(...inputs)`.

src/lib/format.ts
  MONEY. Amounts are bigint, in WHOLE Ugandan shillings. There are no cents.
  Never use `number` for money. Never use floats. Never divide by 100.

    formatUGX(amount: bigint): string
      -> "UGX 4,500,000"
    formatUGXCompact(amount: bigint): string
      -> "UGX 4.5M"  (for tight spaces like Kanban cards; K/M/B)
    parseUGX(input: string): bigint | null
      -> accepts "4,500,000", "4500000", "UGX 4,500,000"; rejects decimals,
         negatives and anything non-numeric by returning null

  DATES. Store UTC everywhere. Display in Africa/Kampala (UTC+3, no DST).
  Use date-fns-tz. Never call toLocaleDateString without an explicit zone.

    formatDate(d: Date | string): string        -> "27 Jul 2026"
    formatDateTime(d: Date | string): string    -> "27 Jul 2026, 14:30"
    formatRelative(d: Date | string): string    -> "3 days ago", "in 2 hours"
    KAMPALA_TZ = 'Africa/Kampala'

src/lib/phone.ts
  Uganda numbers arrive in many shapes and MUST be normalised before they hit
  the database, because contacts.phone_e164 is uniquely indexed.

    normalizeUgandanPhone(input: string): string | null
      Accepts: "0772123456", "+256772123456", "256772123456",
               "0772 123 456", "(0772) 123-456"
      Returns: "+256772123456", or null if it cannot be normalised.
      Rules: strip all non-digits except a leading +; a leading 0 becomes +256;
             a leading 256 becomes +256; a bare 9-digit national number becomes
             +256; validate the result is +256 followed by exactly 9 digits.
      Leave a clearly marked extension point for non-Ugandan numbers — some
      candidates and clients are regional — but do not build it now.

    formatPhoneDisplay(e164: string): string   -> "+256 772 123 456"

src/lib/supabase.ts
  A typed client from env.ts. Single instance, exported once. Import this
  everywhere — never call createClient again anywhere else in the codebase.
  Leave a typed placeholder for the generated Database type; prompt 0.5
  generates the real one.

TESTS: write Vitest unit tests for format.ts and phone.ts covering every case
listed above plus the failure cases. These two files are foundational; a bug in
either corrupts data across every module. `npm run test` must pass.
