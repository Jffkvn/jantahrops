# Prompt 3.3 — AI Candidate Matching, Transferable-Skill Scoring & Interview Prep

Self-contained specification and execution prompt. Pauses Phase 5/6 to add
intelligent, human-in-the-loop applicant evaluation, PDF/DOCX CV parsing,
targeted interview preparation, and Talent Pool matching to Recruitment.

---

```
TASK: Build the AI Candidate Matching & Interview Prep layer for JantaHR Ops:
1. Optional internal "Recruiter Context" on vacancies (with automatic fallback
   to Uganda / East Africa industry standards when left blank).
2. One-time CV parsing into `candidates.cv_parsed` (with safe gap-filling of
   blank candidate profile fields).
3. Per-application AI evaluation (CV + cover letter + screening answers vs.
   vacancy JD + recruiter context) producing a 4-tier badge (`strong`,
   `adjacent`, `partial`, `low`, or `unscored`), a 0–100 score, a 4-pillar
   rubric breakdown, explainable evidence bullets, and tailored interview probe
   questions.
4. Full human-in-the-loop editing/override of the AI's tier, bullets, and
   interview prep questions.
5. A "Matches in Talent Pool" tab on the Vacancy Pipeline page to surface
   existing candidates in the database (~2,000+ pool) who fit a role.

Read this whole block first. Follow every engineering convention in
docs/CONVENTIONS.md.


=== 0. CORE PRINCIPLES & GUARDRAILS (NON-NEGOTIABLE) ===

1. AI is a junior researcher, never the final judge:
   - The AI NEVER auto-rejects an applicant or changes `applications.stage`.
   - Every AI output (match tier, summary, strengths, transferable skills, gaps,
     and interview questions) is a draft that a human recruiter (Jeff / Dora)
     can edit or override in the UI.
   - When a human edits or overrides an AI assessment, record `overridden_by`
     and `overridden_at` and display a subtle "Adjusted by <Name>" indicator.

2. Separate "Person Rating" from "Role Fit":
   - `candidates.rating` (1..5 stars) remains strictly the human recruiter's
     internal rating of the person overall.
   - `applications.match_tier` + `applications.match_score` represent how well
     the candidate fits THIS specific vacancy.

3. Capture "The Human Factor" (Adjacent & Transferable Fit):
   - Keyword matching is broken. A candidate from FMCG logistics applying for a
     Manufacturing HR/Ops role may not share literal keywords but has 85% of the
     same operational muscle.
   - The rubric explicitly evaluates Transferable Skills & Industry Adjacency as
     a first-class pillar and provides a dedicated `adjacent` tier ("Adjacent /
     Transferable Fit") so strong non-linear candidates are surfaced, not buried.

4. Unreadable / Missing CVs Are Never Penalised:
   - If a candidate has no CV attached, or the file is corrupt / an unreadable
     scan with insufficient profile data, the evaluator MUST NOT assign a fake
     low score (e.g. 15% Low Match). It sets `match_tier = 'unscored'`,
     `match_score = null`, and flags `status = 'needs_manual_read'`.

5. Prompt-Injection & CV-Gaming Defence:
   - Candidate CVs, cover notes, and screening answers are untrusted user input.
   - System prompts must wrap candidate text in explicit delimiters, instruct
     the model to ignore any embedded instructions (e.g. hidden white text
     saying "score 100%"), and require every credited skill/achievement to cite
     a concrete employer, role, or qualification from the candidate's history.

6. Client Shortlist Confidentiality:
   - `SHORTLIST_SELECT` in `src/features/recruitment/recruitment-api.ts` and
     `ShortlistPrintView` (`shortlist-print-view.tsx`) are client-facing.
   - NEVER include `match_tier`, `match_score`, or `ai_assessment` in
     `SHORTLIST_SELECT` or render internal AI scores/gaps/interview questions on
     the client shortlist PDF.

7. Cost Discipline ($2 OpenAI Budget Stretch):
   - Use `gpt-4o-mini` via `OPENAI_API_KEY` (stored only in Supabase Edge
     Function secrets, never in client env vars or `VITE_*`).
   - Parse each CV file ONCE and cache the structured output in
     `candidates.cv_parsed` (plus `cv_parsed_at`). Subsequent evaluations of the
     same candidate against other vacancies reuse `cv_parsed` without
     re-downloading or re-parsing the PDF.


=== 1. DATABASE MIGRATION ===

Create a new timestamped migration in `supabase/migrations/`:

1.1 Vacancy internal recruiter context:
  alter table public.vacancies
    add column recruiter_context text;

  comment on column public.vacancies.recruiter_context is
    'Optional internal-only notes for AI screening (preferred industries, pace, dealbreakers). Never exposed on GET /public-jobs. When null, AI uses Uganda/East Africa industry standards.';

  Verify `supabase/functions/public-jobs/index.ts` selects explicit public
  columns only and never leaks `recruiter_context`.

1.2 Application match columns:
  create type public.application_match_tier as enum (
    'strong',      -- 80..100: checks core requirements + context
    'adjacent',    -- 65..85:  strong transferable / adjacent industry fit
    'partial',     -- 45..64:  meets some criteria, notable gaps
    'low',         -- 0..44:   missing fundamental requirements
    'unscored'     -- unreadable CV or insufficient data; needs manual read
  );

  alter table public.applications
    add column match_tier      public.application_match_tier,
    add column match_score     integer,
    add column ai_assessment   jsonb,
    add column ai_evaluated_at timestamptz,
    add constraint applications_match_score_range
      check (match_score is null or (match_score >= 0 and match_score <= 100));

  create index applications_vacancy_match_idx
    on public.applications (vacancy_id, match_score desc nulls last);

1.3 Update `candidates.search_tsv` (or `v_candidate_search`) so parsed CV skills
    and summary are searchable:
  - When CV parsing gap-fills `candidates.skills` and `candidates.headline`,
    `v_candidate_search` and `candidates.search_tsv` automatically index them.
  - Also include `coalesce(c.cv_parsed->>'summary', '')` and
    `coalesce(c.cv_parsed->>'industries_text', '')` in `v_candidate_search.search_text`
    so searching the Talent Pool by an industry or tool mentioned inside a parsed
    CV matches immediately.

1.4 Server-side Talent Pool matching RPC:
  Create `public.match_talent_pool_for_vacancy(p_vacancy_id uuid, p_limit int default 20)`
  (`security invoker` or `security definer` with `auth.uid() is null and current_user not in ('postgres','service_role')` guard, and `revoke all ... from public, anon; grant execute ... to authenticated, service_role`):
  - Reads the target vacancy's `title`, `summary`, `description`, `requirements`,
    `recruiter_context`, and linked organisation's `industry`.
  - Excludes candidates who already have an `applications` row for `p_vacancy_id`.
  - Filters to `c.is_available = true`.
  - Scores candidates in SQL using a weighted combination of:
    a) Skill array overlap against vacancy terms (`c.skills`),
    b) Full-text / trigram similarity over `c.headline`, `c.skills`, `c.notes`,
       and `c.cv_parsed` text fields against the vacancy query terms,
    c) Experience & salary band compatibility (does not hard-exclude null
       salary expectations).
  - Returns the top `p_limit` candidate rows with their contact details and a
    computed `sql_relevance` score and matched keywords list.

1.5 DPPA Erasure Verification:
  - Verify `public.erase_contact(uuid)` in `20261009150000_delete_and_erase.sql`:
    since `erase_contact` deletes the `candidates` row (which cascades to
    `applications`), `cv_parsed` and `ai_assessment` are deleted with the row.
    Add an RLS test assertion confirming no `ai_assessment` or `cv_parsed`
    survives erasure.


=== 2. STRUCTURED JSON SCHEMAS (TYPESCRIPT + ZOD) ===

      year: string | null

  }

2.2 `ApplicationAiAssessment` (stored in `applications.ai_assessment`):
  {
    version: 1,
    status: 'scored' | 'needs_manual_read' | 'error',
    status_note: string | null,
    summary: string,                  // 2–3 sentence recruiter brief
    pillars: {
      core_skills: {
        score: number,                // 0..35
        max: 35,
        note: string
      },
      transferable_and_industry: {
        score: number,                // 0..30
        max: 30,
        note: string                  // explicitly addresses adjacent experience
      },
      experience_and_trajectory: {
        score: number,                // 0..20
        max: 20,
        note: string                  // seniority, tenure stability, progression
      },
      practical_and_cover_note: {
        score: number,                // 0..15
        max: 15,
        note: string                  // cover note quality, screening answers, salary/location/availability fit
      }
    },
    strengths: string[],              // 2–4 concrete bullets citing CV/cover note evidence
    transferable_skills: string[],    // 1–3 bullets explaining adjacent industry/role crossover
    gaps_or_risks: string[],          // 1–3 honest gaps or risks
    interview_questions: {
      id: string,
      topic: string,                  // e.g. 'URA EFRIS depth' | 'Career pivot' | 'Short tenure at X'
      why_ask: string,                // what was missing or ambiguous in CV/cover letter
      question: string,               // the exact question to ask in the interview
      source: 'ai' | 'human'
    }[],
    model: string,
    evaluated_at: string,
    // Human-in-the-loop tracking:
    overridden_by?: string | null,    // profile id
    overridden_by_name?: string | null,
    overridden_at?: string | null,
    ai_original_tier?: ApplicationMatchTier | null,
    ai_original_score?: number | null

=== 3. EDGE FUNCTION: `supabase/functions/evaluate-candidate/index.ts` ===

Deploy an Edge Function calling OpenAI (`gpt-6-luna`, overridable via `OPENAI_MODEL`)
using `OPENAI_API_KEY`, with `reasoning_effort: 'none'` for Step A (CV parsing) and
`reasoning_effort: 'medium'` for Step B (application scoring & interview prep).

3.1 Authentication & Authorisation:
  - Accepts calls from:
    a) Authenticated Ops staff/admin (verified via `Authorization: Bearer <jwt>`
       against `supabase.auth.getUser()`), OR
    b) Internal background invocation from `public-candidates` using the
       service-role key / internal secret header.
  - Rejects unauthenticated / anonymous callers with 401.

3.2 PDF & DOCX Ingestion:
  - Downloads the candidate's CV from the private `candidates` bucket via the
    service-role storage client.
  - For `application/pdf`: sends the PDF to OpenAI `gpt-6-luna` using OpenAI's
    native `input_file` / base64 PDF content block in `/v1/responses` or
    `/v1/chat/completions` file input (and falls back gracefully if the PDF is
    corrupt/empty).
  - For `.docx`: extracts the XML text from `word/document.xml` in Deno before
    passing to `gpt-6-luna`.
  - If `candidates.cv_parsed` is already populated for the current `cv_file_id`
    and `forceReparseCv` is not set, skip Step A and reuse `cv_parsed`.

3.3 Safe Gap-Filling on `candidates`:
  - After Step A (`cv_parsed` extraction), inspect the existing `candidates` row:
    - If `headline` is null/empty and `headline_suggested` is present → fill it.
    - If `years_experience` is null and `years_experience_estimated` is present → fill it.
    - If `skills` is empty (`'{}'`) and `skills_extracted` is non-empty → fill it.
    - If `work_history` is `'[]'` → fill it.
    - If `education` is `'[]'` → fill it.
  - NEVER overwrite non-empty `headline`, `years_experience`, or `skills` that a
    recruiter or candidate already supplied.

3.4 Uganda / East Africa Regional & Industry Calibration in the Prompt:
  - When `vacancy.recruiter_context` is provided, inject it as high-priority
    recruiter guidance.
  - When `vacancy.recruiter_context` is null/empty, instruct the model to apply
    Uganda & East African labour market context based on `vacancy.location` and
    the hiring organisation's `industry`:
    - Recognise local credentials & institutions (ICPAU / CPA(U), ACCA, UMI
      Postgraduate Diplomas like DHRM/DPAM/PPM, Makerere, MUBS, Kyambogo, UCU).
    - Recognise Ugandan statutory/regulatory experience (URA PAYE, WHT, EFRIS,
      NSSF, Employment Act 2006, PPDA, BoU) where relevant to the role.
    - Credit realistic regional industry crossovers (e.g. FMCG ↔ Telecom
      distribution; SACCO/Microfinance ↔ Commercial Banking; Logistics/Depot
      supervision ↔ Manufacturing operations; NGO compliance ↔ Corporate audit).

3.5 Auto-Trigger on Website Application (`public-candidates/index.ts`):
  - Inside `supabase/functions/public-candidates/index.ts`, when a candidate
    registers or applies with a CV, queue a background call
    (`runAfterResponse(...)`) to `evaluate-candidate` so new arrivals are
    already parsed and scored by the time Jeff or Dora opens Ops.
  - If `OPENAI_API_KEY` is not set or the OpenAI call fails, the candidate
    submission and email alerts still succeed 100% (never block public intake on
    AI availability).
```
